# Deliverables

Use these outputs to make solution discussions implementation-ready.

## 1) Technical Discovery Brief

- Problem statement and context
- Functional and non-functional requirements
- Constraints (time, budget, team capability, compliance)
- Candidate options with high-level pros/cons
- Recommendation and rationale

## 2) Architecture Blueprint

- System context and key components
- Data flow and integration boundaries
- Deployment topology
- Security and trust boundaries
- Observability model (logs/metrics/traces)

## 3) Architecture Decision Records (ADRs)

Create ADRs for decisions that are costly to reverse and likely to be questioned later.

Each ADR should include:

- Decision
- Status
- Context
- Options considered
- Trade-offs
- Final rationale
- Consequences

## 4) Implementation Roadmap

- MVP scope and explicit non-goals
- Phase plan and milestones
- Dependencies and sequencing
- Risk mitigation actions per phase
- Success metrics per phase

## 5) Proof-of-Concept Plan

- Hypothesis being tested
- Scope and acceptance criteria
- Timeline and owners
- Required resources
- Exit criteria (go/no-go)

## Practical Defaults

- Start simple; design extension points instead of upfront complexity.
- Validate highest-risk assumptions first.
- Favor reversible decisions early in project life.
- Keep the first milestone focused on proving business value, not architecture perfection.
